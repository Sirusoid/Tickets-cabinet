# Инструкции по работе с Tickets Cabinet

## Назначение

Tickets Cabinet — административная система театра «Жас сахна» для управления спектаклями, расписанием, залами, билетами, клиентами, кассовыми продажами и онлайн-оплатой через BCC.

Стек: PHP 8.4+, PDO, MariaDB/MySQL, vanilla JavaScript/jQuery, Composer.

## Быстрый запуск локально

1. Установить PHP 8.4+ и расширения:
   - `pdo_mysql`;
   - `mbstring`;
   - `openssl`;
   - `curl`;
   - `gd`;
   - `zip`;
   - `xml`.
2. Установить Composer.
3. Создать локальный `.env` на основе `.env.example`.
4. Заполнить параметры базы данных и секрет ссылки билета.
5. Установить зависимости:

```powershell
composer install
```

6. Проверить PHP-файлы:

```powershell
Get-ChildItem -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
```

7. Запустить локальный сервер из корня проекта:

```powershell
php -S localhost:8080
```

Открыть `http://localhost:8080/`.

## Переменные окружения

Реальные значения не хранить в Git:

```dotenv
ZHASSAHNA_APP_ENV=production
ZHASSAHNA_DB_HOST=localhost
ZHASSAHNA_DB_PORT=3306
ZHASSAHNA_DB_NAME=...
ZHASSAHNA_DB_USER=...
ZHASSAHNA_DB_PASS=...
ZHASSAHNA_TICKET_PUBLIC_SECRET=...
```

Секрет можно создать так:

```powershell
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

Не менять `ZHASSAHNA_TICKET_PUBLIC_SECRET` без миграционного плана: старые публичные ссылки на билеты перестанут проходить проверку.

## Авторизация

- `/` перенаправляет гостя на `/login.php`.
- Авторизованный пользователь направляется на `/dashboard.php`.
- Защищенные страницы вызывают `require_login()`.
- После входа регенерируется ID сессии.
- Сессия имеет HttpOnly/SameSite cookie и таймаут бездействия.
- Выход выполняется через POST с CSRF-токеном.

При изменении пользователя в настройках его имя и роль обновляются в текущей сессии.

## Настройки безопасности

Основные параметры находятся в `Настройки -> Безопасность`:

- таймаут сессии;
- лимит неудачных входов;
- время блокировки;
- минимальная длина пароля;
- требования к регистру, цифре и спецсимволу.

После изменения политики паролей она применяется к созданию и изменению пользователей.

## Режим обслуживания

В `Настройки -> Общие` включаются:

- `Режим обслуживания`;
- заголовок сообщения;
- текст сообщения.

При включении:

- `widget/afisha.php` возвращает красивое сообщение для Tilda;
- `tickets/widget.php` показывает то же сообщение в iframe;
- `ajax/public_cash.php` и `ajax/public_payment.php` отклоняют новые публичные операции.

Перед выключением режима обслуживания проверьте афишу и тестовый выбор мест.

## Работа с BCC

Основные точки:

- `tickets/widget.php` — форма покупки;
- `ajax/public_payment.php` — создание платежной сессии;
- `payment/bcc/return.php` — возврат покупателя из банка;
- `payment/bcc/notify.php` — серверное уведомление;
- `includes/payment/bcc_finalize.php` — идемпотентное создание билетов;
- `includes/payment/bcc_refund.php` — возврат `TRTYPE=14`.

После изменения BCC-настроек:

1. Проверить `BACKREF`.
2. Проверить `NOTIFY_URL`.
3. Проверить порт и TLS.
4. Очистить OPcache.
5. Выполнить тестовую покупку.
6. Проверить билеты, PDF и `cash_transactions`.

Не импортировать полный SQL-дамп в production. Для новых настроек использовать страницу настроек или точечную миграцию.

## Клиенты и телефоны

Телефоны нормализуются единым правилом:

- `8 777 000 00 00` -> `+77770000000` в базе;
- `7 777 000 00 00` -> `+77770000000` в базе;
- отображение: `+7 777 000 00 00`.

Не добавлять отдельные локальные правила нормализации в новые модули. Использовать функции из `includes/helper.php`.

## Проверка после деплоя

Проверить:

- `/` для гостя и авторизованного пользователя;
- login/logout и истечение сессии;
- отображение роли и имени в header;
- видимость пунктов меню по роли;
- включение/выключение режима обслуживания;
- публичную афишу Tilda;
- iframe покупки;
- создание и скачивание PDF;
- экспорт клиентов и билетов в XLSX;
- редактирование и удаление клиента;
- доступ к `config.php`, `.env`, `vendor/`, `includes/`, `sql/` и `logs/` должен быть закрыт.

## Безопасность деплоя

- `.env` не коммитить и не пересылать через публичные чаты.
- После раскрытия пароля БД сменить его.
- Установить права `.env` примерно `600`.
- Перезапустить PHP-FPM/OPcache после изменения кода или окружения.
- Удалить временные диагностические и установочные скрипты с production-сервера.
- Проверить работу `.htaccess` или эквивалентных правил веб-сервера.
